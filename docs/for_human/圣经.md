## Matt Pocock 及其 Agent Skills 简介

**Matt Pocock** 是 Total TypeScript 的创始人、前 Vercel / Stately 工程师，也是知名 TypeScript 教育家之一。

为了解决 AI Coding Agent（如 Claude Code、Cursor 等）在实际工程落地中常见的“盲目编码（Vibe Coding）”、“沟通错位”以及“破坏性改动”等痛点，他在 GitHub 上开源了自己的 Agent 技能库：**`mattpocock/skills`**（源自其个人 `.claude` / `.agents` 工作流配置）。

与普通的 AI 工具箱不同，这套 Skill 的核心哲学在于**工程约束与工作流规范（Workflow Enforcement）**。它将资深软件工程师的敏捷拆解、TDD（测试驱动开发）、DDD（领域驱动设计）以及 Git 安全规范注入给 Agent，让 AI 从“随性写代码的助手”转变为“严谨的团队工程搭档”。

---

## 核心 Agent Skills 逐一讲解

Matt Pocock 的 Skills 库主要涵盖需求规划、开发重构、Git 安全与知识管理四大维度（可通过 `npx skills@latest add mattpocock/skills` 按需安装）：

### 1. 需求澄清与规划（Planning & Alignment）

> **解决痛点**：AI 没理解人类的真实意图，仅凭一两句话就盲目动手写代码，导致严重的理解偏差。

* **`/grill-me`（设计拷问）**：开启“苏格拉底式”追问模式。AI 会像严格的架构师一样，就方案的所有分支细节、边界情况向你连续提问，直到彻底理清设计逻辑，杜绝盲目假设。
* **`/grill-with-docs`（结合文档的深度拷问）**：在 `/grill-me` 的基础上，结合项目已有文档构建/补充**领域模型（Domain Model）**，并同步更新项目中的 `CONTEXT.md` 和架构决策记录（ADRs）。
* **`/to-spec`**（早期为 `to-prd`）：将当前与 Agent 讨论澄清的内容总结提炼为结构化的**需求规范（Spec / PRD）**，包含 User Stories，并自动发布至 GitHub/Linear 等 Issue 追踪系统。
* **`/to-tickets`**（早期为 `to-issues`）：将高层级的 Spec 拆解为多个独立可交付的“追踪弹（Tracer-bullet）”级 Issue/Ticket，明确依赖阻塞关系与验收标准。
* **`design-an-interface`**：使用并行子 Agent 快速探索并生成多种 API 或模块接口设计方案供开发者筛选。
* **`wayfinder`（长线路线图）**：面对超大型需求时，将其拆解为一张在 Issue Tracker 上跨会话跟踪的调查任务地图，带领 Agent 逐个突破未知领域。

---

### 2. 软件开发与架构重构（Development & Architecture）

> **解决痛点**：AI 乱改代码导致既有功能损坏，或者写出缺乏边界、难以维护的代码。

* **`/tdd`（测试驱动开发）**：最核心的 Skill 之一。强制 Agent 遵循经典的红-绿-重构（Red-Green-Refactor）循环：先编写一个会失败的测试（Red），再编写刚好能通过测试的最小代码（Green），最后在保持测试通过的情况下重构（Refactor）。
* **`implement`（标准实现）**：根据已定稿的 Spec 或 Tickets 开展编码，在关键节点驱动 `/tdd` 流程，并在 Commit 前自动进行 `/code-review` 代码审查。
* **`improve-codebase-architecture`（架构扫描与改进）**：自动分析代码库中的结构缺陷（如过度拆分的碎片化文件、缺乏清晰边界的模块等），生成可视化 HTML 报告并引导开发者选择性重构。
* **`codebase-design` & `domain-modeling**`：基于《软件设计哲学》思想，帮助 Agent 识别深层模块（Deep Modules）、接缝（Seams）与适配器（Adapters），强化项目的统一语言与领域模型。
* **`triage` / `triage-issue` / `diagnosing-bugs**`：排查与分类 Bug 的专项工作流。引导 Agent 进行有纪律的排错，复现问题并按状态机推进 Issue 的分类与修复。
* **`request-refactor-plan`**：在改动代码前，强制 Agent 先产出分步重构计划。
* **`migrate-to-shoehorn`**：用于库升级与断言迁移的辅助流程。
* **`scaffold-exercises`**：根据现有的生产代码，自动提取并生成教学用的代码练习题、解法和解析。

---

### 3. 工具与 Git 安全防护（Tooling & Git Guardrails）

> **解决痛点**：AI Agent 获得终端操作权限后，偶尔会误执行破坏性指令（如清空未提交的修改）。

* **`git-guardrails-claude-code`**：为 Git 操作设置安全围栏，拦截如 `git push --force`、`git reset --hard`、`git clean -f` 等破坏性指令，并规范 Git Commit 信息。
* **`setup-pre-commit`**：自动配置 Lint、Type-check 与单元测试等 pre-commit hooks，确保不合规代码无法提交。
* **`setup-matt-pocock-skills`**：初始化配置助手，用于设定 Issue 跟踪工具（GitHub / Linear / 本地文本）、分类 Label 规范以及文档存储路径。
* **`ask-matt`**：技能导航路由，当你不知道该选择哪个工作流时，询问它会获得最佳建议。

---

### 4. 知识管理与文档编写（Knowledge & Documentation）

* **`ubiquitous-language`（通用语言构建）**：从代码和文档中提取业务术语，建立统一词汇表。既能减少 AI 的思考 Token 消耗，又能保证变量与函数命名高度一致。
* **`obsidian-vault`**：将 Agent 的上下文与用户的 Obsidian 笔记库保持同步。
* **`edit-article`**：用于撰写/编辑技术文章，检查语气与结构的一致性。
* **`write-a-skill`**：根据描述脚手架生成一个新的 Agent Skill，方便自定义扩展。

---

## 总结

Matt Pocock 的 Skill 库并非又一个沉重的框架，而是**轻量、可组合的工程约束工具包**。

它的核心主线非常明确：**通过“烤问澄清需求（Grill） → 细化任务（Tickets） → 驱动测试开发（TDD） → 加上安全护栏（Guardrails）”的闭环，把 AI 从不可控的代码生成器，约束为严谨可靠的工程协同伙伴**。
