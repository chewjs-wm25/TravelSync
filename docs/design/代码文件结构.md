## 命名规范

| 类别 | 规范 | 示例 |
|---|---|---|
| 文件夹 | 全小写英文语义名；Next.js 动态段使用 `[xxx]` | `app/trips/[tripId]`、`src/components/discovery/` |
| 页面文件 | Next.js 约定 `page.tsx` | `app/login/page.tsx` |
| Route Handler | Next.js 约定 `route.ts` | `app/api/auth/login/route.ts` |
| UI 组件 | 架构 Sub-Component 英文名（PascalCase，`.tsx`） | `GoogleLoginButton.tsx` |
| Zustand Store | 架构 Sub-Component 英文名（PascalCase，`.ts`）；**不沿用**测试文件 `useTestStore.ts` 的 use 前缀 | `TripStore.ts`、`SearchStateStore.ts` |
| 前端业务逻辑 | 架构 Sub-Component 英文名（PascalCase，`.ts`） | `ConflictDetector.ts` |
| 服务端业务逻辑 | 架构 Sub-Component 英文名（PascalCase，`.ts`） | `SessionIssuer.ts` |
| D1 仓储 / KV 访问 | 架构 Sub-Component 英文名（`*Repository` / `*Repo` / `*Store` / `*Access`，`.ts`） | `TripRepository.ts`、`RouteResultCache.ts` |
| 模块 05 补充命名 | 由架构中文描述转写为英文（PascalCase） | `MemberManagementPanel.tsx` |

## 补充说明

1. **通用基础组件**：`src/components/ui/` 放置跨模块通用 UI（如 `Button.tsx`、`Dialog.tsx`、`Input.tsx`、`Badge.tsx`、`Modal.tsx`），按需创建。
2. **自定义 hooks**：模块内 hooks 放 `src/hooks/<module>/`（如 `src/hooks/trip/useTripDetail.ts`），通用 hooks 放 `src/hooks/common/`；模块间经 hooks 通信仅限同模块内部（架构：模块内经 Zustand Store / hooks / Props 直连）。
3. **D1 迁移**：`src/lib/db/migrations/` 存放 16 张表的建表 SQL（如 `0001_init.sql`），表结构见 `数据库设计.md`（待建）。
4. **Server Actions**：若采用 Server Actions 实现服务端逻辑，统一收敛到对应模块的 `src/lib/server/<module>/`，页面内仅做调用编排。
5. **数据访问归属**：模块01 的仓储/KV（`UserRepository` 等）与模块05 各 DAO 为架构表存储标注隐含组件，命名遵循本文档命名规范。
6. **已存文件**：`app/layout.tsx`、`app/page.tsx`、`app/globals.css`、`app/favicon.ico`、`src/store/useTestStore.ts` 为项目已有文件，不属于架构文件树，保留不动。
